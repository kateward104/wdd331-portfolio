Forced Colors: Three Common Problems

Compare the normal appearance with a broken and fixed version. Turn on the preview to see what can go wrong when colors and decorative effects are overridden.

Normal appearance

1. Card boundaries

Problem: the shadow disappears, leaving no visible edge.

Before

Account settings

A shadow defines the card's boundary.

box-shadow: 0 3px 12px #0004;

Broken

Account settings

Without the shadow, the boundary is lost.

box-shadow: 0 3px 12px #0004; /* No alternative boundary */

Fixed

Account settings

A border remains visible in forced colors.

border: 2px solid transparent; @media (forced-colors: active) { border-color: ButtonText; }

2. Icon visibility

Problem: a hardcoded white icon blends into the button face.

Before

White icon contrasts with the dark button.

fill: white;

Broken

The icon matches the button face and disappears.

.broken-icon svg { fill: ButtonFace; }

Fixed

The icon inherits the text color.

.fixed-icon svg { fill: currentColor; }

3. Toggle state

Problem: color alone doesn't communicate whether the switch is on.

Before

Green means on; gray means off.

.track { background: #777; } [aria-checked="true"] .track { background: #176c43; }

Broken

When track colors are overridden, the state is unclear.

.track { background: #777; } /* State depends on color */

Fixed

A thumb border adds a visible state cue.

.fixed-toggle[aria-checked="true"] .thumb { border: 3px double ButtonText; }

Click any switch to toggle it. Each example works independently.

The preview is a visual simulation, not a substitute for testing in actual Forced Colors Mode. In real mode, the browser and operating system determine the final colors.
