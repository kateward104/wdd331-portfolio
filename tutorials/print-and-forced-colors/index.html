Learn about printing defaults and accessibility functions.

Study Topics

Printing

print-color-adjust

Browsers often remove background colors and images to save ink.

This property tells the browser whether it should try to preserve your colors when printing.

  • exact: Ask the browser to preserve the colors as closely as possible.
  • economy: The default. The browser can simplify colors to save resources.


When would you need to use exact?

  • Chart colors represent different data.
  • Color swatches show actual product colors.
  • Alternating table colors help track rows


The key decision is whether color is content or decoration. Exact will do the best it can to match your look.

Detection

Forced Colors Mode

Users with accessibility needs may enable a high-contrast color scheme. The browser replaces many of your website's colors with system-selected colors to make content easier to distinguish.

CSS lets you detect this mode and fix components that become difficult to understand.

Forced Colors Mode is about ensuring people can see and understand your interface.


System color keywords:

  • Canvas = Background color
  • CanvasText = Text color on the background
  • LinkText = Hyperlink color
  • ButtonFace = Button background color
  • ButtonText = Button text color
  • Highlight = Selected item background
  • HighlightText = Text on a selected item


Example:

@media (forced-colors: active) { .card { border: 2px solid ButtonText; } }

This gives the card a border using a color selected by the user's system, rather than forcing your own brand color onto them.

Control

forced-color-adjust

This property is easy to confuse with the forced-colors media query.

Forced Colors Mode is about ensuring people can see and understand your interface.

  • forced-colors detects whether the mode is active.
  • forced-color-adjust controls whether an element's colors are automatically adjusted.


There are three values for forced-color-adjust:

  • auto: The default. The browser can replace colors.
  • none: The browser will not replace colors.
  • inherit: Preserves the parent's color through inheritance, primarily for SVG use.

Example:

@media (forced-colors: active) { .color-swatch { forced-color-adjust: none; } }


If a color swatch represents an actual paint color or product color, changing it could make the information incorrect. But there's a catch: opting out can also disable the browser's text backplate, which helps ensure text contrast.

Use forced-color-adjust: none sparingly, only when preserving the original color is genuinely necessary. Never use it just because you dislike how your design looks in high-contrast mode.

Common Problems and How To Fix Them Demo

Problem 1: A card's border disappears

  • Your card relies on box-shadow to separate it from the background. Forced Colors Mode removes box shadows, so the card's edge disappears.
  • Fix: Add a transparent border.
  • Ex: .card { box-shadow: 0 2px 8px #0002; border: 1px solid transparent; }
  • Aftermath: the border is invisible in normal mode but gives the browser a boundary it can make visible in Forced Colors Mode.

Problem 2: An icon disappears

  • An SVG icon has a hardcoded fill color that becomes indistinguishable from the new background.
  • Fix: For a single-color icon, use currentColor.
  • example: < path fill="currentColor" d="..." />
  • Aftermath: currentColor inherits the element's text color, allowing the icon to follow the browser's adjusted color. For meaningful multicolor artwork, such as a logo, the solution may be different.

Problem 3: A toggle's state becomes unclear

  • A custom toggle uses only green and gray backgrounds to distinguish on from off. When the colors are replaced, both states may look the same.
  • Fix: Add another visual distinction, such as a border, outline, or position change.
  • Aftermath: The user should be able to tell whether the toggle is on or off without relying on color alone.
