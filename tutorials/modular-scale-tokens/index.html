Rounding with round()

This text demonstrates CSS rounding.

Example of Rounding (not live time):

Pre-Rounding-Code: round-size: calc(var(--base) * pow(var(--ratio), 3));
Calculated size: 31.25px

Post-Rounding-Code: round(nearest, var(--round-size), 4px)
Rounded Result: 32px


When to Use Rounding?

CSS calculations can produce fractional values, such as 31.25px. Most of the time, this fits the scale that we have chosen, which is for the better. However, sometimes we want values to follow a consistent increment, such as whole pixels or a 4px spacing system (often used for precise spacing or grids). That's when round() becomes useful. Just be careful because rounding can slightly change the relationship between values in a modular scale.

ratio and base

The key to creating a fluid type scale is creating a base size, and multiplying it by a ratio to create an effective scale.

Ex: var(--base) * var(--ratio);

pow()

pow() raises a base to an exponent. This takes two arguments: a base and an exponent. pow(base, exponent). Use calc with pow in order to create an exponent for the base.

Ex: calc(var(--base) * pow(var(--ratio), 1));

round()

round() rounds a value. This takes two arguments: a value and a rounding increment. round(value, rounding-increment).

Ex: round(nearest, calc(var(--base) * pow(var(--ratio), 3)), 4px)

simpler approach

Approach 1: One fluid base

Only the base size uses clamp(). Every other size is calculated from it.

:root {
--ratio: 1.25;

/* Only the base is fluid */
--base: clamp(1rem, 0.9rem + 1vw, 1.25rem);

/* Everything else inherits that fluidity */
--size-md: var(--base);
--size-lg: calc(var(--base) * pow(var(--ratio), 1));
--size-xl: calc(var(--base) * pow(var(--ratio), 2));
--size-2xl: calc(var(--base) * pow(var(--ratio), 3));
--size-3xl: calc(var(--base) * pow(var(--ratio), 4));
}

  • --base grows and shrinks with the viewport.
  • Every other size multiplies that changing base by the ratio.
  • All sizes grow proportionally, maintaining their mathematical relationship.

The tradeoff: Your largest headings might grow more than you want on wider screens because they're growing proportionally with everything else.

more control

Approach 2: Individual fluid sizes

Instead of making the base fluid, each size gets its own clamp().

:root {
--ratio: 1.25;
--base: 1rem;

/* Each size has its own fluid range */

--size-md: clamp(1rem, 0.95rem + 0.3vw, 1.125rem);
--size-lg: clamp(1.25rem, 1.1rem + 0.8vw, 1.875rem);
--size-xl: clamp(1.56rem, 1.4rem + 1.5vw, 2.5rem);
--size-2xl: clamp(1.95rem, 1.8rem + 2.5vw, 3.5rem);
--size-3xl: clamp(2.44rem, 2rem + 4vw, 5rem);
}

  • Every size has its own minimum, preferred growth rate, and maximum.
  • Body text can grow slowly while headings grow more dramatically.
  • You can prevent large headings from becoming excessively large.

The tradeoff: You have more control, but you must write and maintain a separate clamp() for every size. The original ratio relationship is no longer guaranteed at every viewport width.

The takeaway
A fluid base makes your entire scale responsive while preserving the proportional relationship between sizes.
Individual clamps give you more control over how each size responds to the viewport, but requires more CSS and can change the relationship between sizes.
