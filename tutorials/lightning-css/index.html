Everything You Need to Know About Lightning CSS

Learn about CSS markers, backdrops, and selectors.

Study Topics

Pseudo-elements let CSS target special pieces of the browser's UI or an element that aren't normal HTML elements.

Step 1

Install Node.js

  • Check what version of node you have with node --version.
  • If it is a version number like v20.x.x or higher you are good, otherwise, go install LTS (Long Term Support) from nodejs.org.
Step 2

Create a package.json file

  • Make sure you are in the right folder in the terminal, not just selecting the file!
  • npm init -y will do this for you.
  • These act as the project's instruction sheet by recording which packages the project needs and which commands you want to be run.
  • If you have pnpm installed you can use pnpm init instead.
Step 3

Create a .gitignore file with the following content: node_modules/

  • node_modules is essentially the storage room for packages which can contain thousands of files so we want to skip it in .gitignore.
Step 4

Lightning CSS needs two packages: Lightning CSS itself and a file watcher for automatic rebuilds during development./

  • npm install --save-dev lightningcss -cli chokidar -cli
  • At this point, this is the entire install since Lightning CSS handles bundline, vendor prefixing, minification, and syntax lowerings in one package.
Step 5

Add a Build Script

  • Open package.json and find the "scripts" section. Replace the default "test" script with a build command:
  • "scripts": { "build": "lightningcss --bundle --minify --targets \">=0.25%\"css/main.css -o dist/styles.css", "watch": "chokidar \"css/**/*.css\" -c \"npm run build\" --debounce 600" }
  • npm run build runs once, if you change your CSS files, you will need to run it again.
  • npm run watch starts a watcher that monitors your source CSS files. When you save a CSS file, it triggers another build automatically. It stays running in the terminal until you stop it with Ctrl+C.
  • Here's What Each Flag Does:
    --bundle: takes all @import files and inline css into one output/file.
    --minify: gets rid of comments and whitespace.
    --targets ">=0.25%": tells Lightning CSS which browsers to support. It will automatically add vendor prefixes where needed and, when possible, lower modern CSS syntax into equivalent older syntax for those browswers. The >= 0.25% value means "any browser with at least 0.25% global usage," which is a reasonable default.
    -o dist/styles.css: the output file. The dist/directory will be created automatically.
Step 6

Run the Build Script

  • npm run build
Step 7

Update index.html

  • Update index.html to link to "dist/styles.css" instead of "css/main.css" since it has the updated page.

Things to Remember

For Continous Editing

If you want to continue editing CSS without constantly running the build script, use npm run watch.

  • npm install --save dev chokidar-cli
  • add a watch script to package.json alongside your build script:
    "scripts": {
    "watch": "chokidar 'css/**/*.css' -c 'npm run build' --debounce 600"
    }
  • Run npm run watch
  • Every time you edit CSs, it will wait 600 milliseconds then runs your script. Press Ctrl+C to stop watching.

Using npx

npx gives you the ability to see how Lightning CSS will impact your code, but it isn't permanent.

  • npx lightningcss-cli --bundle --minify --targets ">=0.25%" css/main.css -o dist/styles.css
